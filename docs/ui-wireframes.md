# UI 线框 v1（草案）

原则（约束 10）：**默认简洁聊天**，按需展开编辑区与专业面板。多端（Web / Desktop / Mobile）共用同一应用服务与数据模型，界面层可独立迭代。本轮不开发完整 UI，以下为基线线框。

---

## 1. 信息架构

```
主聊天 (默认)              按需展开 (侧栏/底部面板)
─────────────             ─────────────────────────
- 对话流                   - 编辑器（代码/文档）
- 输入框                   - STM32 构建面板
- 模型选择器               - EDA 面板（原理图/PCB 状态）
- 工具/连接状态徽标         - 飞书连接器面板
- 任务/运行时间线入口       - 文件树与资产列表
```

## 3. 展开：编辑器 + STM32 构建面板

```
┌─────────────── 编辑器 ───────────────┬──────── STM32 构建 ────────┐
│ // main.c                            │ 工具链: ( )CubeIDE ( )Keil  │
│ int main(){ ... }                    │ 目标: [Debug ▾]             │
│                                     │ [构建] [打开日志]           │
│                                     │ 退出码: 0 ✓                 │
│                                     │ 产物: firmware.hex          │
│                                     │ [烧录] (需显式确认)         │
└─────────────────────────────────────┴─────────────────────────────┘
```
- 构建/烧录都由**执行节点**完成，UI 只发起与展示；烧录需显式确认，不自动执行（约束 4、任务书 七「不擅自烧录」）。

## 6. 任务/运行时间线（恢复可见性）

```
run_3 ─ 12:01 创建
  ├─ step_1 model    ✓ 提出 fs.read
  ├─ step_2 tool     ✓ fs.read 执行
  ├─ step_3 model    ✓ 回答
  └─ 状态: succeeded
run_4 ─ 12:05 创建
  ├─ step_1 model    ✓ 提出 build
  ├─ 执行节点离线
  └─ 状态: waiting_executor (重启后可继续/终止)
```
- 让「执行节点离线、重启、未知状态」对用户可见，避免静默丢失（任务 F）。

## 7. 多端基线

| 端 | 载体 | 说明 |
|----|------|------|
| Web | React + SPA | 首版交付目标，浏览器访问 |
| Desktop | Tauri / Electron 壳 | 复用 Web + 本地常驻执行节点 |
| Mobile | 响应式 Web / 轻量壳 | 首版以响应式为主，原生后置 |

---

## 8. 状态与反馈原则

- 任何工具调用显示「提出 → 批准 → 执行 → 结果」四态，体现约束 4。
- 凭据相关操作一律不显示明文；配置只接受引用。
- 失败/未知/副作用操作均显式提示，不静默重试。
